# Decisions: release publishing

How a release of Havooch reaches people outside its GitHub Release: the Homebrew tap and the skill's own repository. Read this file before you change `.github/workflows/release.yml`, `scripts/update-tap.sh`, `scripts/update-mate.sh`, the cask, or the place the skill installs from. Add an entry for each new decision: the date, what was decided, and why.

## 2026-10-08

From #121 "Set up the Homebrew tap for releases" and #122 "Install the skill from a release archive, not a repository clone".

- **One tag publishes to three repositories.** A `v<version>` tag runs `release.yml` in this repository. The `release` job publishes the zip and its SHA-256 as a GitHub Release. The `tap` job writes the cask to `yahyabedirhan/homebrew-tap`. The `mate` job writes the skill to `yahyabedirhan/havooch-mate`. The tap and havooch-mate have no connection to each other: people install the app with Homebrew or `scripts/install.sh`, and the skill with `npx skills add yahyabedirhan/havooch-mate`.
- **This repository is the source.** The cask is `Packaging/homebrew/havooch.rb`, and the skill is `.agents/skills/havooch-mate/`. Change them here, in the same pull request as the app change they describe. Do not edit the copies in the tap or in havooch-mate, because the next release writes over them.
- **The skill has a repository of its own because of clone size.** For an `owner/repo` source, the skills CLI (v1.7.1) clones the full repository, public or private. It skips the clone only for the owners on its allow list (`vercel`, `vercel-labs`, `heygen-com`, `remotion-dev`). A shallow clone of this repository is 269 MB and took 56 s. havooch-mate is less than 1 MB. A release archive as the source was tried first in #126 and dropped as more than the problem needs.
- **The skill and the app have no version match.** The `main` branch of havooch-mate holds the skill of the latest release, and it has no tags. People install the latest skill and keep the app up to date. A skill change merged here reaches people at the next release.
- **The mate job owns only the skill's files.** `scripts/update-mate.sh` removes each tracked file in havooch-mate and copies the skill in. It keeps the repository's own files: `README.md`, `LICENSE`, `AGENTS.md`, `CLAUDE.md` and everything under `docs/`. Add a path to `own_files` in the script before you add a new kind of file to havooch-mate. `--dry-run` shows the change without a commit.
- **One token writes to both repositories.** The workflow's own `GITHUB_TOKEN` can write only to this repository. The `tap` and `mate` jobs push to other repositories, so they use the Actions secret `TAP_TOKEN`. It is a fine-grained token of the maintainer, with Contents: read and write on `homebrew-tap` and `havooch-mate` only. Its name says "tap" because the tap needed it first. Without the secret, both jobs skip with a notice, and the release still publishes. A job with an expired token fails, and the release still publishes.
- **The token expires after one year.** The maintainer keeps a reminder one week before it expires. To renew it, make a new token with the same access, replace `TAP_TOKEN`, and delete the old token. Then run the failed `tap` and `mate` jobs again with `gh run rerun <run id> --job <job id>`.
- **The three repositories stay public.** Homebrew and the skills CLI download without a login.
- **User-facing text names no maintainer detail.** The README, the cask caveat, the repository descriptions and havooch-mate's README say what to install and how. Where a file is maintained and how it is published go in this file and in `AGENTS.md`.
