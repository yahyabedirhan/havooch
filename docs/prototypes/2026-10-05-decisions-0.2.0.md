# Decisions for 0.2.0: the sidebar, one surface and native parts

The itemized decisions for Havooch 0.2.0, taken from the maintainer's review of the 0.1.0 screenshots and the thread-UX prototype round (branch `prototype/thread-ux`, `docs/prototypes/thread-ux/`; variant 02 "Inbox and Detail" won). The spec `Spec: Havooch 0.2.0` (#36) holds the same decisions in structured form, and `docs/low-level-design.md` (L36 to L39 and later) holds how the build carries them out.

They continue the numbering of [the 0.1.0 decisions](2026-10-05-decisions.md) and replace five of them:

## 3. The right sidebar

| # | Decision |
|---|---|
| 3.10 | The sidebar shows either the **thread list** or one **thread view**. It opens on the thread list. There is no expanded thread any more. |
| 3.11 | The thread list groups the threads by who must act next, in this order: **Needs you** (an open question), **With agent** (sent, acknowledged or working), **Queued** (a queued message), **Done** (the rest). A thread is in the first group it matches. Inside a group, threads keep time order, General first. Each group header shows its count and stays at the top while the list scrolls; Queued's says `⌘↩ sends them all`. A summary line under the title reads `6 threads · 1 needs you · 2 queued`. |
| 3.12 | A row has an 88 × 50 pt keyframe thumbnail with its region outlines (a symbol for General), the number and time, the state chip with glyph and name, a relative time (`3m`) and a two-line preview that names the writer (`You:`, `Asks:`, the agent). The thread view has no keyframe: the stage shows it. |
| 3.13 | The thread view has a top bar: Back (with the count of the other threads that need the person), the number and time, Previous and Next. Escape goes back. Opening a thread view (a row, a pin, a badge, a notice, `thread show`) pauses the player on the thread's frame. It slides in from the trailing edge with the sidebar's spring; with Reduce Motion it fades. |
| 3.14 | Chat style. The person's messages are trailing, in `bubblePerson`, with a small tail and no avatar; the state, the region tag and the time go on a quiet line under the bubble. The agent's messages are leading, with a 24 pt avatar showing the agent logo (5.15), in `bubbleAgent`; the agent's name shows once at the start of each run. A question is a card in `bubbleQuestion` with a `question` border and the heading "<agent> asks"; an answer is tinted with `question`. A queued message has a dashed `stateQueued` outline, Edit and Delete on hover, and edits in place (Enter saves, Escape cancels). The region crop stays an attachment under its message (3.5's attachment rule stays). |
| 3.15 | One **composer** at the foot of the sidebar, above the footer, replaces the field of a thread. In a thread view it follows up on the thread (queued, 2.13) or, with an open question, answers it at once (2.16): "Follow up on #3", or "Answer #3 · goes at once" in the question colour. In the thread list it writes at the playhead, to the thread of that exact frame or a new thread (3.8): "Reply on #3" or "New thread at 0:12". A General toggle writes to General; a region drawn on the frame shows as a chip with a remove button. Enter queues, Shift+Enter adds a line, ⌘↩ sends the queue. The field grows with its text up to a limit. It keeps one draft per target thread, in memory. |
| 3.16 | The stage popover for comments stays as it is (1.2, 2.7). |
| 3.17 | A right-click menu on a message has Edit, Delete and Copy where they apply; on a row, Open, Show on video and Delete queued messages. |

## 5. The overall look and layout

| # | Decision |
|---|---|
| 5.12 | **One surface.** Hairlines and space separate the parts of the window, not background colours; bubbles stay only for messages. The header, the stage, the player bar, the sidebar and its footer draw `window`. A `separator` hairline is on the sidebar's leading edge and above the footer. A row under the pointer takes `controlHover`; the row of the thread on the stage sits in a `well`. The sidebar colour tokens (`sidebar`, `sidebarSection`, `sidebarRowSelected`, `sidebarRowHover`, `header`, `bar`, `stage`) are gone from the built-in themes; a user theme that still sets one loads, since an unknown token is ignored. The footer keeps the player bar's height (4.9). |
| 5.13 | **System surfaces.** A theme may set a surface token to `system`: the native macOS surface for it (the window background, the native toolbar, a material for popovers and notices). `Palette` stays the only place that makes a colour. Default Light and Default Dark set their surfaces to `system`; Dimmed and the eight VS Code themes keep painted values. All chrome changes together. |
| 5.14 | **Native parts.** `ContentUnavailableView` for the empty first screen and for "No threads yet" (the drop target stays as an overlay); native borderless buttons in place of the custom quiet button style; the system focus ring on text fields; a `Settings` scene (⌘,) with the theme picker, beside the View › Theme menu. Where the spec says nothing, the macOS convention wins. |
| 5.15 | **Agent logos.** The agent avatar is the logo of the agent harness, ported from Shipyard (`yahyabedirhan/shipyard` at `74b9695`) with its notices: Claude, Codex, OpenCode, Cursor, Pi, Gemini, GitHub Copilot, Amp and Droid. The listener session's name chooses it ("Claude Code" shows the Claude logo); no CLI flag changes. An unknown name shows the sparkle symbol. |

## 6. Control

| # | Decision |
|---|---|
| 6.1 | `thread show <thread>` replaces `thread expand <thread>`; `thread list` shows the thread list. `state --json` names the thread the sidebar shows in `sidebar.thread`, `null` for the list, in place of `expanded`. |

## Left for a later effort

Quick-reply buttons on questions, a live line of what the agent does, unread dots on new replies, and `.inspector` or `List` in place of the custom sidebar column.
