## Decisions the maintainer took (grilling round)

- The demo switches the running app to the demo folder in the same window. No relaunch.
- Cmd+W closes the window and the app keeps running in the Dock. The Dock icon shows the window again with the same video. Cmd+Q quits, and the next launch shows home.
- In the player, a click on the Havooch mark in the header goes home. A header entry opens a new video without going home.
- Thumbnail: simplicity first. Use the last-stopped frame only if it costs no more than the first frame.
- Unavailable videos: a dimmed card, an "unavailable" symbol and a trash button that removes the card.
- The maintainer gave every other small decision to the agents. List each decision an agent took alone in the pull request description, in its own section.

## Decisions this session took alone (put them in the PR too)

- The theme stays on the person's data during the in-app demo. The control socket does not move and no demo pointer is recorded for it.
- The trash button removes the card from recents only. The review stays on disk, keyed by content hash. (The maintainer said "removed from the application completely"; deleting review data is destructive, so this session chose recents only. Flag it in the PR.)
- File > Close Video uses Shift+Cmd+W, because Cmd+W is the window's Close.
- No thread counts or unread dots on cards. Thumbnails are in memory only, made with `AVAssetImageGenerator`.
- Recents are `recents.json`, 10 entries, matched by content hash, migrated from `recent.json`.
- A new `havooch app home` command and `state` fields `screen` and `recents`, so agents can check home without clicks.
